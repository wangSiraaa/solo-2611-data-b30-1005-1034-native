# 密封多单位拍卖与保证金清算（合成实现）

纯合成账户与虚构拍卖规则，**不连接任何真实金融服务**：无加密密封、真实支付、税费或信用授信。金额一律为**整数分**，账户/场次/标的均为虚构。

## 规则

- 每场卖出 `K` 个同质单位（1–10），每买家最多一个有效 bid；bid 含正整数数量、整数分单价、稳定 `bid_id`。
- 截止前可**完整替换**（更高 `revision` + 新冻结凭据）或**撤销**；截止后不可改标。
- 排序：单价降序、`bid_id` 升序，分配 `min(qty, 剩余)` 直到 `K` 用尽，允许最后一标部分成交。输入顺序不参与并列判定。
- 统一成交价 = **所有获配单位中的最低投标价**；无人获配则无成交价。
- 每买家订单额 = 获配数量 × 统一价；未成交单位不收费。
- 上限：最多 5 买家/场、每场 10 单位、本部署总计 3 场。

## 保证金口径

每个买家恒满足：

```
累计入金 = 可用 + 有效冻结 + 已扣款
```

- 冻结资金按 hold 绑定到**单一拍卖**，不能同时支持另一场投标。
- 结标后按**冻结结果**消费：获配者以统一价扣款并释放余量（扣款额不超过该 hold 冻结额），未获配者全额释放；hold 置为 `CONSUMED`/`RELEASED`，重复结算不再扣款。
- 数据库唯一索引 `ux_charge_once(auction_id, hold_id) WHERE kind='CHARGE'` 作为最后一道防线。
- 冻结余额在 `BEGIN IMMEDIATE` 事务内派生，两个连接争最后一分钱只有一个能成功。

## 一致性设计

| 关注点 | 实现 |
| --- | --- |
| 投标凭据核验 | 拍卖端在投标/冻结时直接读 `holds` 行，核对买家、场次、金额、`ACTIVE` 状态，绝不信任调用者自填“已冻结” |
| 撤标/换价原子性 | 撤销标记、新凭据安装、旧凭据释放处于**同一事务**，不存在旧款已释放但旧 bid 仍可结标的窗口 |
| 结标结果不可变 | 截止时一次性计算并写入 `settlements.allocations_json`；重开、重试、付款失败均复读同一份 |
| 响应丢失 | 每个写操作带 `request_id`，响应持久化在 `receipts`；相同请求重放返回已提交结果，不同请求复用 id 报冲突 |
| 结算续跑 | 每个 hold 的仓库操作使用确定性 `request_id`（`settle:<auction>:<bid>`），崩溃后任意调用者可按实际状态续做，不会双扣 |
| 待决状态 | `settlements.status` = `FROZEN → CLEARING → CLEARED`，部分结算可见且可继续 |

## 虚构印务场（展签装版）

印厂在原清算办妥后才开工。每个中标买家的原稿登记为**一块独一字版**（`(auction, buyer)` 唯一），带允许的左/右头、纸边套准孔序与可否翻转；未获配或未清算的原件不能登记，字版也不能复制到两个头。

- **装版方向与孔序**：反装把孔序左右镜像；二合一须两个具名版分放两头，固定单排套准针要求两头有效孔序逐位一致，空头不限制套准。`trial_proof` 只读试拼，返回实际版号、左右方向、有效孔序和对不上的针位。
- **工单目标**：恰好交付每人获配数。优先级为**先少撕废，再少拉纸，最后少换版**（全平则合并成更少更大的批次）。一张纸每个非空头产一张展签，已交足者的额外展签当场撕废、绝不转人；空头不计撕废。
- **换版口径**：不同头或不同方向即换版，首版免费；同版连印不另计。最多 6 块字版/单、每批不超 10 张，可从不同真场汇成一批。
- **求解**：先跑零撕废确定性搜索（每个装版取占用版剩余最小值，唯一拉纸数，状态极小）；不可行时用最小装版覆盖下界（换版）与最小用纸下界直接判定 `PressInfeasible`，否则在有界搜索里求最小撕废方案。150 组随机用例与暴力枚举结果一致。
- **一次性制造**：已在某工单拉印的字版不能再排进另一工单，对账从原始行独立核验来源、每版交付恰等于获配数、撕废不转人、跨工单不重复制造。

## 复跑

```bash
python3 -m unittest tests.test_scenarios -v
python3 -m unittest tests.test_press -v
python3 -m examples.run_demo                       # 临时库
python3 -m examples.run_demo --db demo.sqlite3     # 持久库；多次运行自动命名空间隔离
python3 -m examples.press_demo                     # 印务场三场景，临时库
python3 -m examples.press_demo --db press.sqlite3  # 印务场持久库
```

演示逐步打印：

1. 入金后可用余额；
2. 冻结如何占款、冻结不足如何拒绝投标；
3. 换价时旧 hold 原子释放、新 hold 生效；
4. 截止排序与统一价（及最后一标部分成交）；
5. 按统一价真实扣款、余量释放；
6. 重复结算不双扣；
7. 扣款已提交但响应丢失后，用同一 request id 续跑；
8. 排序解释；
9. 从原始事件重算每个买家的资金守恒；
10. 独立对账（账户、获配总数、扣款总额）。

## 已验证场景

`python3 -m unittest tests.test_scenarios` 覆盖：

- 并列截断由 `bid_id` 决定，而非输入顺序；
- 部分成交 + 统一价低于部分中标者报价，订单按统一价计；
- 撤标/换价原子替换冻结；
- 冻结不足、伪造凭据、跨买家/跨场次凭据、已释放凭据被拒；
- 同一 hold 不能支撑另一场投标；
- 重复结算、并发结算、扣款响应丢失后续跑均只扣一次；
- 截止后投标/撤销/修订被拒；扣款失败不改变冻结榜单；
- 两连接争最后余额仅一个成功；
- 空场无成交价；
- 限额与“每买家一个有效 bid”；
- 对账能从原始事件发现被删除的扣款。

印务场（`tests/test_press.py`）另覆盖：

- 孔序一致的两版二合一拉 2 张零废；孔序改成 01 且不可翻则试拼报针位错位，只能两个单头各拉；
- 只发一张纸对不兼容两版判 `PressInfeasible`；
- 零换版时同版连印、弱势买家超额当场撕废且不转人；准一次换版则先合拉一张再单头补，零废；
- 反装镜像孔序及“不可翻则禁止反装”；
- 未获配/未清算不能登记字版、同一原件唯一字版、左右头方向限制；
- 已拉印字版不能再排工单；幂等重放不重复印展签；跨真场拼批；
- 独立对账发现撕废展签被改挂到别的买家。
