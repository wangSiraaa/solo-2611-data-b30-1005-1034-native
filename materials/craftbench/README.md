# craftbench — 陶套筒烧前工艺凭单与装窑/装箱联合工单

在不改写既有 `extcontract`（精确有限类型合同、适配、修订感知摄入）的前提下，
新增一层**烧前**工艺决策。合成尺寸规则，不对应任何真实窑炉操作；所有数值用
`fractions.Fraction` 精确表达，没有浮点、没有四舍五入。

## 要解决的问题

矩形陶套筒的装箱内衬必须在**烧成以前**裁好。每款泥料/火程登记若干组候选
成形比例对 `(横向比例 rw, 纵向比例 rd)`（正有理数），分别乘坯件横、纵内外
尺寸。同一炉、同一款的几件共用同一组未知比例；不同炉次可各取不同组。只有
对**所有允许的实际炉况**都合格的固定套法，才允许裁内衬。

## 三条硬纪律

1. **只认实际签读。** 校样行绑定 *款 + 实样号 + 测向*，给出坯尺寸与烧后闭
   区间。只有写端实际给出并签读（`signed=true`）的测量约束比例；缺测列的
   默认值只是旧表排版占位，凭单记到 `ignored_placeholders`，绝不参与判断。
2. **横纵观察共同作用于整组比例对。** 同一实样（`sample_id`）的横、纵观察
   一次拿整组 `(rw, rd)` 去核对，结构上不可能拿 A 组的横值拼 B 组的纵值。
   不同实样是不同炉次，可各自印证不同的组；款级存活组取并集。一个实样把全
   部候选组矛盾掉即整款退校；仅横向回单时多组可保留。
3. **固定套法须对全部允许炉况合格。** 内件烧后外宽/外深必须分别**严格**小于
   外件同向烧后内宽/内深，擦边即不许。同炉同款锁同一比例组；异炉比例独立，
   取两组存活集合的笛卡尔积。

## 模块

| 文件 | 职责 |
|------|------|
| `ratio.py` | 精确有理数、闭区间、由坯尺寸+烧后区间反推比例界 `lo/b..hi/b` |
| `model.py` | 情景解析：款/件/校样/承架/目标；硬上限（6 件、3 架、每款 ≤3 组） |
| `voucher.py` | 可独查工艺凭单：逐实样整组核对、排除依据、同炉/异炉联合尺寸 |
| `planner.py` | 装窑枚举 + 最少套叠链（箱）穷举；两种目标；错误的逐轴最坏对照 |
| `intake.py` | 用旧 `extcontract` 接入口摄入试烧来单，盖写到情景 |
| `cli.py` | `voucher` / `order` / `joint` / `intake` 命令 |

## 合同与固定读者（旧接入口，未改动 extcontract）

* `trial-writer-contract.json`（`tw1`）：写端 8 列；`observed_lo/hi` 为
  nullable DECIMAL(12,4)，`signed` 为 INT8（0/1）。
* `trial-reader-contract.json`（`tr1`）：同构读者，nullable 的 observed 列带
  显式 `default "0"`——只在整列缺失时补，不给已存在的 null 填值。
* `reader_client.py`：与 745 的固定读者同构，以真实子进程核读
  `reader-records/v1`，输出行数与数值列精确合计。

## 端到端演示

```bash
PYTHONPATH=. python3.11 examples/run_craft_demo.py
```

覆盖：基准 `[4,5]` 两组都活 → 架费 2 一箱（零架费只能两箱，因分炉存在
`5 > 24/5` 的反例炉况）→ 更正行 `[5,5]` 经 supersede 重发 → 普通分炉即一箱
零架费、旧工单不改 → 横纵反向比例的虚构炉况对照 → 箱位上限求最低架费 →
全组矛盾退校与占位忽略。

## 两种优化目标

* `min_boxes`（可给 `fee_budget`）：最少运输箱数，平手再省架费；
* `min_fee`（必须给 `box_cap`）：在车辆箱位上限内求最低须租架费。

枚举规模被硬上限压住（≤6 件、≤3 架、每款 ≤3 组），装窑划分与套叠森林全部
穷举，结论可逐条回放；套叠用位掩码备忘 DFS 求最大边数，边按字典序选择，
输出确定。

## 逐轴最坏边界为什么会虚构炉况

`planner.axiswise_worst_check` 是**故意保留的错误对照**：它让横向、纵向各自
独立取最坏边界。当两件**共架**时，横纵必须由同一组比例对产生；逐轴最坏会把
pair0 的横向最坏与 pair1 的纵向最坏拼成一个任何单组比例都实现不了的开口（见
`cross-axis-demo`：虚构出内件 `(2,2)`，实际只有 `(2,1)` 与 `(1,2)`）。工单
从不使用该函数，只在测试与凭单对照中暴露这种错误。
