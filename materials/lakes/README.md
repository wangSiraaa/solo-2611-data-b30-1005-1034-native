# 湖名迁版材料

两个材料都由 `python3 -m slabwater lakes <file>` 复跑。每版作为 `opens=0` 的闭口计划发布，
命名只读发布产品的逐格水深 `storage`（= `level − height`），不读格高、不读蓄水总量。

## `example.json`

闭口 `C=3`、一行五格。

| 版 | 地形 | 发布水深 |
| --- | --- | --- |
| 旧 | `[0,2,1,3,1]` | `[3,1,2,0,2]` |
| 新（第 2 格降到 1） | `[0,1,1,3,1]` | `[3,2,2,0,2]` |

旧深度 2 档：`{0}`、`{2}`、`{4}` 三块；青(4) 在 `{0}`，石(3) 在 `{2}`。

- **新地形**：深度 2 档只剩 `{0,1,2}` 与 `{4}`。青、石都能且只能领 `{0,1,2}` 这块
  （各重合 1 格），但每块至多一名 → 留青得 **4**，石进入失名清单。
- **还原地形**（新版仍 `[0,2,1,3,1]`）：两块分离，各领一片，保 **7**。
- **还原地形 + 名额收为 1**（`max_names=1`）：留青得 **4**；石所在块 `T2#1` 仍独立存在，
  只是未领名。

## `conflict.json`

“各自单看重合最大”同时采用会错挂湖系的例子。

| 版 | 地形 | 发布水深 |
| --- | --- | --- |
| 旧 | `[1,2,4,2,2,2]`（C=4） | `[3,2,0,2,2,2]` |
| 新（第 2 格填平到 2） | `[1,2,2,2,2,2]` | `[3,2,2,2,2,2]` |

旧名：浅A(2) 与深A(5) 同属 **A 湖系**（深A 是浅A 的支湖），浅B(4) 属 **B 湖系**。

- 深 2 档：旧版两块 `{0,1}`（浅A）、`{3,4,5}`（浅B）；新版连成一块 `{0..5}`。
- 深 3 档：新版块 `{0}` = 深A。

单看：浅B 领深 2 大块（重合 3），深A 领深 3 小块（重合 1）——合计 **9** 分，且都在获准档内。
但同取时，深A（A 湖系）的新块 `{0}` 被浅B（B 湖系）的新块 `{0..5}` 包含，等于把旧的 A 系
支湖挂到 B 湖系下。

求解器因此拒绝该组合，改让本系祖先浅A 领深 2 大块（重合 2）、深A 仍领深 3 小块，保留
**7** 分；`kinship` 给出浅A→深A 的关系，`old_nested`、`new_nested`、`cross_system=false`，
且 `verified_from_depth_product=true`，可直接用发行水深复核。
